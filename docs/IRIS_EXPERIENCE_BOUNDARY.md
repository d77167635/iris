# IRIS Experience and Traversal Boundary

## Purpose

IRIS is **one complete hierarchy intelligence relational ontology financial life state ecosystem**.

There are no two sides, no separate Financial Life experience and Intelligence experience, and no rule that an intelligence or education surface must be free of user-specific financial information.

Every IRIS surface is a traversal surface of the same governed hierarchy.

## 1. Universal surface rule

**Any IRIS surface may expose any portion of the complete intelligence hierarchy when that content is supported by the user's governed evidence and/or legitimately derived by IRIS from that evidence.**

The surface name does not determine whether user data may appear. Evidence state, derivation state, lineage, uncertainty, execution state and certification/publication rules determine eligibility.

## 2. One complete hierarchy

```text
IRIS
↓
Financial-Life Reality
↓
Provider / User / Authoritative Evidence
↓
Observed State
↓
Canonical Financial-Life State
↓
Relational Ontology
↓
Temporal / Statistical / Behavioral / Causal Intelligence
↓
Risk / Opportunity / Prediction / Scenario / Decision / Consequence / Outcome / Learning
↓
Cross-Domain Intelligence
↓
Higher-Order Intelligence
↓
Recursive Derived Intelligence
↓
IRIS Features / Reports / Questions / Explanations / Evidence / Education / Workspaces
↓
User
```

Education is contextual explanation of the same hierarchy.

Evidence inspection is traversal into the same hierarchy.

Reports are traversal/publication surfaces of the same hierarchy.

Financial-Life state is part of the same hierarchy.

## 3. Forward traversal

```text
provider observation
→ governed evidence
→ observed state
→ canonical Financial-Life State
→ relational ontology
→ intelligence
→ higher-order intelligence
→ recursive composition
→ feature/report/explanation
→ user
```

## 4. Reverse traversal

```text
user result / report / answer / explanation
→ producing intelligence
→ upstream dependencies and relationships
→ canonical Financial-Life State
→ exact governed evidence
→ source-field observation
→ provider observation
```

Exact factual reverse traversal requires exact persisted lineage.

Conceptual educational explanations must be explicitly conceptual and must never be represented as actual user evidence.

## 5. Evidence and epistemic boundaries

The one-system rule does not weaken evidence governance.

These states remain distinct:

```text
available
≠ consented
≠ authorized
≠ provider response received
≠ observation persisted
≠ evidence certified
≠ normalized
≠ intelligence-consumable
≠ intelligence consumed
```

And:

```text
unknown
≠ unavailable
≠ unobserved
≠ hypothetical
≠ predicted
≠ inferred
≠ derived
≠ observed
```

Unknown is never silently converted to zero.

## 6. Reports and education

Reports, education and explanations may coexist with user-specific evidence when the displayed content is legitimately supported.

For example, an IRIS explanation of observed spending may include:

- the observed fact;
- its canonical classification;
- relationships that were actually derived;
- the intelligence that produced the finding;
- uncertainty and limitations;
- supporting evidence;
- the transformation or calculation used; and
- the path back to source evidence where persisted lineage exists.

Education therefore explains the user's actual intelligence when appropriate. It is not a data-free substitute for it.

## 7. Provider observability

Provider observability remains a distinct **external source/provider capability**, not a second IRIS side.

Provider products, availability, consent, authorization, entitlement, billing, response receipts and provider observations enter the same governed hierarchy.

Provider capability is not provider observation.

## 8. Current domain boundary

IRIS has eight authoritative domains:

1. Authentication
2. Transactions
3. Balance
4. Identity
5. Assets
6. Liabilities
7. Investments
8. Statements

The current executable Sandbox boundary may be seven domains until real banking support exists. Statements must not be simulated or fabricated to fill the deferred domain.

## 9. Implementation rule

When an existing surface is reviewed, classify content by semantic role rather than by an assumed side:

1. Provider evidence → governed evidence hierarchy.
2. Observed Financial-Life state → governed state hierarchy.
3. Derived intelligence → intelligence hierarchy.
4. User-specific report/result → publication surface of the same hierarchy.
5. Education/explanation → contextual representation of the same hierarchy.
6. Evidence/provenance → reverse-traversal representation of the same hierarchy.
7. Runtime machinery → execution infrastructure supporting the same hierarchy.

Nothing is moved to a separate architectural side merely because its visual presentation differs.

## 10. Non-negotiable

There is **one IRIS system**.

The user may move through any supported depth of that system from reality to intelligence to meaning and back to evidence.

The evidence boundary governs truth. It does not create two sides.
