# IRIS Capability & Product Roadmap

This roadmap is the engineering source of truth for IRIS capability state and proof state. It does not divide IRIS into separate Financial Life and Intelligence sides.

## 0. Authoritative architecture correction

IRIS is **one complete hierarchy intelligence relational ontology financial life state ecosystem**.

There are no two sides, no two experiences with separate data boundaries, and no data-free Intelligence/Education side.

The complete hierarchy is:

```text
IRIS
↓
Financial-Life Reality
↓
Provider / User / Authoritative Evidence
↓
Observed State
↓
Canonical Financial-Life State
↓
Relational Ontology
↓
Temporal / Statistical / Behavioral / Causal Intelligence
↓
Risk / Opportunity / Prediction / Scenario / Decision / Consequence / Outcome / Learning
↓
Cross-Domain Intelligence
↓
Higher-Order Intelligence
↓
Recursive Derived Intelligence
↓
IRIS Features / Reports / Questions / Explanations / Evidence / Education / Workspaces
↓
User
```

Every stage is a potential traversal surface of the same graph.

### Universal surface rule

**Any IRIS surface may expose any portion of the complete intelligence hierarchy when that content is supported by governed evidence and/or legitimately derived by IRIS from that evidence.**

Education is contextual explanation of the same intelligence. Evidence inspection, reports, explanations, questions and workspaces are not separate architectural sides.

The data/evidence state determines what may be shown and how it must be labeled. The name of the screen does not create a factual boundary.

## 1. Forward and reverse traversal

### Forward

`provider observation → governed evidence → observed state → canonical Financial-Life State → relational ontology → intelligence → higher-order intelligence → recursive composition → feature/report/explanation → user`

### Reverse

`user result/report/explanation → producing intelligence → upstream relationships → canonical state → exact governed evidence → source-field observation → provider observation`

Exact factual reverse traversal requires persisted lineage. Conceptual explanations must never be presented as actual user evidence.

## 2. Eight authoritative domains

1. Authentication
2. Transactions
3. Balance
4. Identity
5. Assets
6. Liabilities
7. Investments
8. Statements

Statements is architecturally Domain 8. The current Sandbox execution boundary may remain seven domains until real banking. Deferred domains must never be simulated or fabricated.

## 3. Evidence-state contract

```text
available
≠ consented
≠ authorized
≠ provider response received
≠ observation persisted
≠ evidence certified
≠ normalized
≠ intelligence-consumable
≠ intelligence consumed
```

Epistemic states:

```text
unknown
≠ unavailable
≠ unobserved
≠ hypothetical
≠ predicted
≠ inferred
≠ derived
≠ observed
```

Unknown is never represented as zero. Persistence is not semantic proof. Prediction is not observation. Scenario is not observation. Correlation is not causation.

## 4. Products versus Reports

Provider products are external/provider capabilities that can potentially contribute evidence.

IRIS Report Products are governed publication definitions over the IRIS intelligence graph.

```text
Provider Product count ≠ Report Product count
Report Product count ≠ produced result count
produced result count ≠ certified result count
```

Each count must be sourced from its own governed catalog/runtime state. No count may be fabricated to make screens appear symmetrical.

# 5. Governing certification chain

Every capability is tracked through:

`Architecture Defined → Contract Defined → Schema Implemented → Runtime Implemented → Independently Executable → Evidence Verified → Exact Evidence Boundary Verified → Semantic Lineage Verified → Report Product Defined → Report Product User-Controlled → Report Product Surfaced → Interaction Verified → Deployment Verified → End-to-End Certified`

A later state never implies an earlier state is certified.

The build is dependency-ordered. Implementation priority is not an architectural split.

# 7. Read-only boundary

Current scope remains read-only.

No ACH, RTP, FedNow, card movement, transfer, withdrawal, trade, deposit or other money movement is part of the current intelligence product.

Round-Ups remain a feature within the hierarchy and do not define the architecture.

# 8. Anti-fabrication gate

Fake AI data is strictly prohibited.

Never create or present fabricated:

- users;
- accounts;
- transactions;
- balances;
- income;
- debt;
- spending;
- provider observations;
- report results;
- outcomes;
- probabilities/confidence values; or
- causal conclusions.

Actual provider Sandbox records may be used as Sandbox test evidence. They are not production truth.

If evidence is absent, the system must use an appropriate unknown, unavailable, insufficient-evidence, not-observed or deferred state.

# 9. Certification gates

Each authoritative domain requires an independent runtime gate covering the applicable evidence path, persistence, semantic interpretation, lineage, and publication boundary.

The complete system must prove:

1. forward provider/evidence traversal;
2. canonical-state formation;
3. intelligence consumption;
4. exact lineage;
5. reverse traversal;
6. publication eligibility;
7. user-control behavior; and
8. end-to-end user interaction.

# 10. Definition of done

IRIS is not complete because a page renders, a route exists, a table contains a row, an endpoint returns HTTP 200, or a capability is registered.

A capability is complete only when its contract, schema, runtime, evidence boundary, semantic transformation, lineage, publication state, interaction and deployment proof satisfy the applicable certification gate.

The final product remains one complete IRIS hierarchy intelligence relational ontology financial life state ecosystem from provider evidence through user understanding and back again.
